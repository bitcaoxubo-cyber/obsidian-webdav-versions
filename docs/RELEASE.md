# 0.4.0-beta.3：手机暂存 next 缺失恢复

本次修复针对“删除后点击立即同步，提示文件 next 不存在”的报告。

## 已确认与未知

已在隔离模型中复现：下载/替换事务已写入日志，但临时载荷 next 丢失，后续同步会持续失败。模拟带中文错误、无 ENOENT 编码的原生 stat 也会阻断恢复。

尚未读取报错手机的事务目录和原生调用栈，因此不能确定手机最初为何丢失 next，也不能将模型复现等同于真机根因确认。

## 修复

- 仅在临时 next 缺失时，交叉核验原 apply 日志、旧文件哈希及远端修订，再取回同一个内容哈希的载荷。
- 对取回内容执行大小限制和 SHA-256 校验；再次确认本地恢复记录未变化后，恢复暂存文件并继续原事务。
- 中文原生报错只在私有事务目录清单也确认文件不存在时才作为缺失处理。普通笔记的读取错误不会被当成删除。
- 已存在但损坏、不可读的载荷不覆盖；日志不一致、历史缺失和断网时保留现场。恢复期间出现的新本地内容不会被覆盖。
- 常规本地恢复保持原先行为，完整载荷存在时无需额外联网。远端协议及持久化状态格式不变。

## 验证

261 项自动测试通过，包含原 243 项和新增 18 项。覆盖首次下载、替换、中文错误、断网重试、错误哈希、日志不匹配、远端历史缺失、恢复期间用户编辑、旧嵌入式日志、已完成写入和删除冲突。1000 笔记加 10 个附件的 v2 性能阈值通过，常规场景计数及字节与 beta.2 基线一致。

没有在真实 WebDAV 上写入，也未在报错 iPhone 上验证。没有修改既有 beta.2 发布附件。

## 更新与验收

先备份手机本地库，在 BRAT 选择固定 Release 版本 `0.4.0-beta.3`。保留设置、笔记和 local-state，不需要重建库。手动更新时只替换 main.js 与 manifest.json。更新后保持前台运行一次“立即同步”，确认错误消失，并检查对应冲突及文件删除结果。若仍报错，请保留完整错误与状态，不要删除恢复目录或手工创建 next。
