# 大目录存储布局迁移

此操作改变远端插件内部目录结构，需要先确认并暂停所有客户端。正常更新插件不会自动迁移。

## 为何需要迁移

PROPFIND 不一定提供分页。有的服务只返回 10000 个直接子对象，并不给出截断错误。只补读本机已知的记录，仍会漏掉其他设备的新记录，因此不能忽略缺失或清空历史。

v2 将对象放入 `obsidian-webdav-versions-v2/<首位十六进制字符>/<完整哈希>.json|blob`。最多 16 个一级目录，每个目录单独读取。如某个分目录再次达到 10000 项，插件会暂停，不能把截断列表当作完整结果。

## 前提与操作

1. 备份本地库、插件、配置和 local-state，暂停所有设备的同步。
2. 将所有设备准备更新至 0.3.0-beta.1 或更新版。
3. 在同一 WebDAV 服务的独立测试子目录，验证迁移、冷启动读取及回退。
4. 在可信 Mac 上调用 `src/migration.js` 的 `migrateStorage(options, hooks)`。`options` 是地址、用户名及仅在内存中使用的密码；不得将密码写进源码、命令参数、日志或仓库。
5. `hooks.saveRevision(name, bytes)` 必须把版本 JSON 保存到库外的私有备份目录；`hooks.checkpoint(record)` 追加本地迁移日志；`hooks.knownIds` 传入现有本机状态中的全部已知修订 ID。
6. 迁移逐批移动对象，校验内容与版本关系。中断可用同一参数继续；未完成时新客户端拒绝同步。
7. 全部通过后写入格式完成标记。先手动同步和核验，再逐台恢复自动同步。

本操作使用 HTTPS、GET、PROPFIND、MKCOL、PUT 和同站点 MOVE，不调用 DELETE。对象名是内容或修订哈希，移动不改变正文、附件内容和历史关联。

## 回退

暂停所有客户端，再调用 `rollbackStorage(options, hooks)`。它从各分目录枚举对象，校验后移回旧位置，把布局元数据及重复副本归档保留。回退不清空本地同步状态，也不声称解决旧布局原有的目录数量上限。

如同一路径存在不同内容、对象损坏或真正缺失，操作会暂停并保留现场；不要自行删除迁移标记或 local-state。

## 验收标准

- 新布局能列出全部旧版本，并覆盖参与迁移设备的已知修订集合。
- 父版本完整，附件引用存在，内容哈希匹配。
- 冷启动客户端重建同样的正文和冲突副本。
- 并发编辑、离线修改、重命名和删除语义保持一致。
- 回退后旧对象路径、内容及修订 ID 与迁移前相同。
- 公开交付只含通用代码、合成测试和说明，不含用户 WebDAV 地址或凭据。
