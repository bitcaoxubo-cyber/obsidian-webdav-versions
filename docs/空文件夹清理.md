# 空文件夹清理 · 0.4.0-beta.5

## 1. 摘要

电脑只自动清理本轮同步实际移除文件后留下的空父目录；手机、历史残留和本机自己清空的目录进入确认窗口第四组。清理不读写远端，不改变协议或 `local-state/`，仅在 `data.json` 增加本机保留名单。**电脑与 iPhone 真机清理尚未验收。**

基线：`7aab13c1a6b543c5ae1cd3be376c4b1c7babca88`（beta.4）；分支 `fix/empty-folders`。实现与发布核验没有操作真实笔记或写入真实 WebDAV。最初以 PR #5 交付；用户随后明确授权合并发布，程序代码保持原核验版本，发布记录以 GitHub tag/release 为准。

## 2. 验收结果

**414/414 项通过：原 358 项全部保留，新增 56 项。** 以下目录操作均在真实临时目录或适配器沙箱中执行。电脑使用 `DiskVault`；新手机测试明确关闭 `supportsAtomicEmptyDirectoryRemoval`，模拟真实手机。测试文件：`test/f1-empty-folders.test.js`、`test/f2-empty-folders.test.js`、`test/f3-empty-folders.test.js`。

**清理批次只进入一次原引擎队列；文件事件不会在批次中途启动另一同步轮。**

## 4. 清单与保留名单

**清单是会话内展示数据，保留名单是唯一新增的持久化数据。**

同步结果新增 `emptyDirectories: Array<{ path: string, subdirectoryCount: number, containsDSStore: boolean }>`，按路径排序，只返回最上层合格目录。子目录数不含自身；`.DS_Store` 标记聚合整个子树。前三组 `confirmations`、自动弹窗键和文件待确认计数不包含这份数组。

`local.directorySnapshot` 是已有全量 list 顺带生成的 Map，记录每个目录的 `files`、`folders` 两个 Set 和 `blocked`。隐藏目录/文件及符号链接阻止候选；电脑普通 `.DS_Store` 例外单独记录，手机不例外。成功应用文件删除与清理会更新该内存记录，下载文件通过当前视图保护，无需再次扫描。增量轮只沿用上次清单；手动清理才在所选子树内重新枚举。

设置新增 `retainedEmptyDirectories: string[]`，例如 `["archive", "papers/keep"]`，路径经校验、去重并排序。保留条目代表整个子树；祖先由于含有保留子树也不再作为候选。列表只属于本机，不在设备间传输；reset 仅清空设置，下一全量轮重新识别，不立即清理。

引擎 `cleanDirectories(paths, callbacks)` 与 sync/confirm 共用 `_enqueue`，返回 `{cleaned: string[], skipped: string[], emptyDirectories}`。计数按完成的顶层选择项计算；非递归清理若仅完成部分子目录，顶层项算跳过，剩余目录在后续全量轮重算。中断不新增日志。任何同步失败都会清除本轮清理上下文，须成功完成一次同步后才能再清理。

## 6. 已知限制

**目录清理不代替文件同步，也不提供跨设备的空目录同步。**

- 手机及电脑 `.DS_Store` 回收站路径的最后复查与原生调用之间仍有极短空档；此时写入的文件可能随目录进入回收站，可恢复。收到事件、已有盘上内容、打开的笔记编辑器或后台状态会阻止清理，但不能把这条路径变为原子的空目录删除。
- 电脑接收其他设备的删除后，会删掉对方可能故意保留的空目录；再次放入文件时目录会重建。本机用户自己删光留下的目录进入确认窗口。
- 手机不自动清理。没有原子空目录删除声明时，不尝试 adapter.rmdir(false)。
- 运行 beta.4 或更旧版本的设备不会得到本次清理功能。历史旧客户端的协议兼容性不等于它具有本版保护或界面。
- 一台设备手动清理空目录不会传播到其他设备；各设备分别识别、保留或清理。
- 清单可能在两次全量轮之间过期，仅用于显示；实际清理依赖重新校验。打开该目录下的笔记编辑器时，即使编辑器声称已保存，也保守跳过回收站路径。
- 适配器/文件系统报错可能中断批次，已完成项不回滚；后续全量会重建剩余清单。不能用清空 local-state 消除错误。
