# 0.4.0-beta.1 性能优化报告

## 1. 摘要

稳态空闲轮库内文件读取从2020次降到0次、同步JS哈希从8092次降到0次，本地状态写入为0。首次下载哈希量降至103.50 MiB，1000/2000篇实测哈希增长比为2.052。20ms请求延迟下，下载/上传墙钟分别为B1串行对照的36.1%/57.9%；冷启动每文件HTTP总比值含固定会话开销，略超5次目标。

## 4. 用户可见的行为变化

手机防抖15秒、桌面5秒；空闲轮询60→120→240→300秒。首次、前台恢复、手动、解决冲突、错误后的下一轮和每10分钟全量扫描。没有Obsidian事件的外部修改等下一次全量轮；“深度校验同步”忽略缓存。面板显示耗时、库内读取、内容及状态哈希字节、HTTP请求、同步类型和轮询间隔。近期2秒文件会出于竞争保护重读，因此立刻连点手动同步不保证读取恒为0。

## 5. 未达标项

- 冷启动上传HTTP：v1 5059、v2 5102，阈值均为5050。每文件传输主体5次，但首次布局探测、目录确认/建桶额外计入总数；完整回读安全校验保留。对应断言仍失败，未从分母分子中扣除开销。
- 阶段A的增量轮为130次适配器调用，超过100；阶段B状态保存改造后已达标。
- 阶段B、规模翻倍及延迟阈值已逐项核对；除上述冷启动HTTP总量外，其余目标均通过。

## 6. 未实施项

B2b未实施：大附件上传后仍完整回读及SHA-256校验。B5b未实施：没有测试用真实飞牛目录，未验证桶mtime/ETag变化，仍每次列所有桶。未增加运行时依赖、端到端加密、历史清理、后台同步或远端迁移/回退行为；未写真实WebDAV、未打tag、未发布Release。

每200操作/5秒仍会写完整检查点，严格渐进复杂度仍有O(N²/200)的快照成本；本报告只证明给定1000/2000文件规模实测接近线性。内存预算约束已计划/保留的传输payload，不是进程总内存上限；readBinary/requestUrl自身整包缓冲和极窄文件增长竞态可能产生瞬时额外分配，大小复查和SHA会拒绝违规结果。实际iPhone内存、输入流畅性和发热仍待真机检查。

## 7. 兼容性与回退

远端修订字段、ID、命名、v1/v2目录、blob字节不变，0.1.1固定夹具通过。同一受支持布局可混用旧新客户端；0.1.1/0.2不能访问v2这一既有边界不变。

本地状态仍version:1，读取旧双槽状态及嵌入pending。新增手机hash cache、独立pending、完成收据及主快照收据水位；临时/完成文件均只在local-state。缓存缺失或损坏可重建；主状态、日志或未被检查点覆盖的完成收据损坏会停止，不以清空状态掩盖。

中断后直接装回0.3.0-beta.1不安全：旧版忽略独立pending和完成收据。先备份整个库含local-state，用新版本成功完成前台手动全量同步，确认无错误/待处理、独立pending为空且完成收据已入检查点，再停用插件降级。若新版本不能恢复，保留现场和未同步文件，通过新空白库核对远端恢复，不能删除状态强行继续。
