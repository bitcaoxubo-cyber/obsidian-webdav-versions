# 0.4.0-beta.1 性能优化报告

## 1. 摘要

稳态空闲轮库内文件读取从2020次降到0次、同步JS哈希从8092次降到0次，本地状态写入为0。首次下载哈希量降至103.50 MiB，1000/2000篇实测哈希增长比为2.052。20ms请求延迟下，下载/上传墙钟分别为B1串行对照的36.1%/57.9%；任务发布者在补充任务C2中将上传阈值修正为每新增文件的边际请求数，v1/v2实测均为5.000次，全部最终阈值通过。

## 4. 用户可见的行为变化

手机防抖15秒、桌面5秒；空闲轮询60→120→240→300秒。首次、前台恢复、手动、解决冲突、错误后的下一轮和每10分钟全量扫描。没有Obsidian事件的外部修改等下一次全量轮；“深度校验同步”忽略缓存。面板显示耗时、库内读取、内容及状态哈希字节、HTTP请求、同步类型和轮询间隔。近期2秒文件会出于竞争保护重读，因此立刻连点手动同步不保证读取恒为0。

有待处理文件时，重试间隔从60秒逐步拉长到300秒；未处于失败等待期时，文件有新改动仍按手机15秒、桌面5秒防抖。连续编辑时至少每60秒同步一次；同步失败后等待60秒再试，网络恢复或回到前台时立即重试。

无（按任务发布者在补充任务C2中修正后的最终口径）。阶段B、规模翻倍及延迟阈值全部通过。

阶段A曾有130次增量调用，已由阶段B降至71次；旧的“上传总请求÷文件数≤5”把固定会话开销算入，现按明确授权改为新增文件的边际请求数。所有原始请求总数继续保留，没有跳过校验或扣除实际请求。

## 6. 未实施项

B2b未实施：大附件上传后仍完整回读及SHA-256校验。B5b未实施：没有测试用真实飞牛目录，未验证桶mtime/ETag变化，仍每次列所有桶。未增加运行时依赖、端到端加密、历史清理、后台同步或远端迁移/回退行为；A–C验收阶段未写真实WebDAV、未打tag、未发布Release；本次D2按任务发布者授权发布预发布版，验收和核验记录见第11节。

每200操作/5秒仍会写完整检查点，严格渐进复杂度仍有O(N²/200)的快照成本；本报告只证明给定1000/2000文件规模实测接近线性。内存预算约束已计划/保留的传输payload，不是进程总内存上限；readBinary/requestUrl自身整包缓冲和极窄文件增长竞态可能产生瞬时额外分配，大小复查和SHA会拒绝违规结果。实际iPhone内存、输入流畅性和发热仍待真机检查。

## 7. 兼容性与回退
