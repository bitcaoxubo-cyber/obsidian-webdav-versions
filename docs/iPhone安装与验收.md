# iPhone 安装与验收（不使用 iCloud）

本文件适用于 `0.4.0-beta.4`。**真实 iPhone 验收尚未完成。** 请先备份本地库，并在独立测试库按下表验收。

本版识别丢失同步记录后的旧副本，并把需要决定的文件集中到确认窗口。所有连接同一远端的电脑和手机都要升级：旧设备仍可能把已经删除的文件重新上传。

## 更新已安装的插件

**不要卸载重装，也不要删除插件文件夹。** 卸载会一起删除同步记录。先备份手机本地库，保留笔记、`data.json` 和全部 `local-state/`。

在 BRAT 的插件列表中编辑 `bitcaoxubo-cyber/obsidian-webdav-versions`，把固定版本改为 `0.4.0-beta.4`。已经添加过仓库的设备不必重新添加。固定版本不会自动切到其他版本，之后升级时仍需修改固定版本号。电脑端可以使用相同的 BRAT 更新方式，详见 [README：更新插件](../README.md#更新插件)。

手动更新时，先关闭 Obsidian，用新版本的 `main.js`、`manifest.json` 覆盖默认目录 `<手机本地库>/.obsidian/plugins/obsidian-webdav-versions/` 中的同名文件，再打开 Obsidian。不要覆盖或删除 `data.json`、`local-state/`。手机不便访问插件目录时优先使用 BRAT。

所有设备更新后，保持前台，手动运行“立即同步”，再查看确认窗口。已经有笔记的手机更新时不需要重建空白库。只有首次接入的测试库或正式库，才按后文创建空白本地库。

## 已经卸载重装过的设备

本版本不会把同一路径中与历史内容完全相同的旧副本重新上传。别处已更新的会更新到最新内容；别处已删除的会留在本机，出现在“本机的旧副本”一组中。

检查路径后，可以删除本机旧副本，或选择“保留并重新同步”。暂时关闭窗口时文件仍会保留，不会因下轮同步而自动删除。内容与历史版本不同的本地修改仍保留，并按并发修改规则处理。

## 安装到独立测试库

1. 更新 iPhone 上的 Obsidian，至少为 1.11.4。
2. 新建空白测试库，例如“飞牛手机测试”；关闭 Store in iCloud / 保存到 iCloud。在“文件”App 中确认位于“我的 iPhone → Obsidian → 飞牛手机测试”。
3. 设置 → 第三方插件 → 启用第三方插件。浏览社区插件，搜索 **BRAT**，安装并启用。
4. 在 BRAT 添加 `bitcaoxubo-cyber/obsidian-webdav-versions`，选择固定版本 `0.4.0-beta.4`；也可使用同版本程序文件手动安装到测试库。
5. 启用 **WebDAV Versions · 飞牛同步**，在设置页核对版本号。

公开仓库安装无需 GitHub Token。GitHub 用于安装和更新插件，日常笔记同步走飞牛。

## 独立测试配置

1. 在飞牛现有 WebDAV 目录下创建独立测试子目录。Mac 另开一个空白测试库，与手机测试库使用这个子目录；不要拿正式笔记做删除或冲突实验。
2. 手机填写该子目录的完整 HTTPS 地址、用户名和设备名 `iPhone`。Mac 测试库设备名填 `Mac-Test`。
3. 在各自设备通过密钥选择器输入密码。不要复制其他设备的 `data.json`、`local-state/`、待上传内容或密钥。
4. 自动同步保持关闭。先测试连接、保存设置，再手动“立即同步”。连接测试只证明目录可读，上传测试才证明写权限。
5. 命令面板提供“立即同步”“查看同步状态”“深度校验同步”“查看同步冲突”。

若远端已迁移为 v2，所有客户端至少需要支持 v2 的版本；要同时获得本次旧副本保护，全部设备须升级到 `0.4.0-beta.4`。不要删除同步记录来绕过兼容性或完整性提示。

## 用确认窗口处理旧副本和冲突

同步结束后，有新条目时集中弹出一个窗口；同样的条目不会每轮重复弹出。也可以随时运行“查看同步冲突”。

- **本机的旧副本**：选择“删除本机副本”或“保留并重新同步”，可批量处理。
- **删除冲突**：先检查保留文件的设备及内容说明。只有“内容与删除前相同”的文件进入批量删除；“删除后有改动”的文件要逐个决定。
- **旧版本冲突**：检查较新版本所在文件，再选择“采用较新版本”，可批量处理。
- 其他普通冲突仍需比较内容，必要时手工合并并保存，再使用“采用当前文件解决冲突”。

批量操作先确认数量，一次确认只进行一轮同步。内容改变、未保存输入或冲突变化会使相关文件被跳过，其他文件可以继续处理；结束时会提示跳过数量。

确认删除通过 Obsidian 的回收站接口进行。如果“设置 → 文件与链接 → 已删除文件”设为“永久删除”，插件会阻止此操作。先选系统回收站或 Obsidian 回收站，再回到窗口继续。

## 手机空目录与暂存恢复

本版停止自动清理手机空文件夹，以免整理目录时影响刚出现的文件。文件删除与移动照常同步；文件已经删除但旧空文件夹仍在，是本版保留的行为。需要整理时，请在 Obsidian 中检查后自行处理空目录。

已有的暂存恢复功能继续保留。此前“next 不存在”错误的最初原因仍未确认，尚未检查报错手机的完整事务现场。若再次出现，保留完整错误信息和本地库，不要删除恢复目录或手工创建 `next`。

## 接入正式笔记库

1. 先完成真机测试，并保留正式库的独立备份，再安排正式升级。
2. 首次接入时，在 iPhone 新建空白本地正式库，关闭 Store in iCloud，安装固定版本插件。已有库只更新插件，不重建库、不卸载。
3. 填入 Mac 正式库使用的同一 WebDAV 地址和用户名，手机独立保存密码。所有设备升级后再恢复同步。
4. 关闭自动同步，手动首次同步。不要把 NAS 里的版本对象目录直接拷贝成笔记库。
5. 保持前台，使用稳定 Wi-Fi、接电，并留足整个库及临时工作空间所需容量。128 MiB 是手机单文件上限。
6. 检查正文、附件和可见文件数量，再逐项处理确认窗口。远端版本记录数量不等于当前文件数量。
7. 确认结果后开启自动同步。打开后先等同步，编辑完等“已同步”再离开应用。

同步只在 Obsidian 前台运行，不承诺锁屏持续同步；不依赖 iCloud Drive，也不要求购买 Obsidian Sync。

## 故障与回退

- 提示同步暂停时，先保留本地库和错误信息。不要删除 `local-state/`，其中可能有尚未上传的内容。
- 若本版本不适用，先关闭插件及自动同步，保留所有本地内容；回退也采用覆盖程序文件的方式，不用卸载来代替更新。
- 中断后不能直接降级到不认识新同步日志的旧版本。先备份整个库，用当前版本完成恢复与手动同步；不能恢复时保留现场，由独立空白测试库核对远端内容。
- 固定版本能防止未经验证的新版本自动替换；不要仅为处理一台设备的问题让其他设备长期停留在缺少旧副本保护的版本。
