# iPhone 安装与验收

本文适用于插件 `0.4.0`。笔记存在 iPhone 本地，不使用 iCloud。

下面的 [真机验收表](#真机验收表) 还没有逐项做完。第一次在 iPhone 上使用，请先备份，并按本文先在一个测试库里试，通过后再接入正式笔记。

已经装过插件、只想升级的，直接看 [更新已安装的插件](#更新已安装的插件)。

## 安装到测试库

1. 把 iPhone 上的 Obsidian 更新到 1.11.4 或更高版本。
2. 新建一个空白库，例如「飞牛手机测试」。创建时关闭 Store in iCloud（保存到 iCloud）。建好后在「文件」App 里确认它在「我的 iPhone → Obsidian」下面。
3. 进入「设置 → 第三方插件」，打开第三方插件开关。浏览社区插件，搜索 BRAT，安装并启用。
4. 在 BRAT 里添加 `bitcaoxubo-cyber/obsidian-webdav-versions`，固定版本选 `0.4.0`。
5. 启用「WebDAV Versions · 飞牛同步」，到它的设置页顶部核对版本号。

仓库是公开的，安装时不需要 GitHub Token。GitHub 只用来下载和更新插件，笔记同步走的是你自己的 WebDAV。

## 配置并第一次同步

测试时不要用正式笔记做删除和冲突实验。

1. 在飞牛现有的 WebDAV 目录下新建一个单独的测试子目录。在 Mac 上另建一个空白测试库，也连到这个子目录。
2. 在手机的插件设置里填写这个子目录的完整 HTTPS 地址和用户名，设备名称填 `iPhone`。Mac 测试库的设备名称另取，例如 `Mac-Test`。
3. 在「WebDAV 密码」处新建密码。每台设备各自输入，不要从别的设备复制 `data.json` 或 `local-state/`。
4. 「自动同步」先不开。点「测试连接」，再点「保存设置」，然后运行命令「立即同步」。
5. 按 [真机验收表](#真机验收表) 逐项测试。

测试连接只说明目录读得到，能不能写要到第一次同步上传时才知道。

如果远端已经迁移到 v2 存储布局，所有设备的插件都要是支持 v2 的版本（`0.3.0-beta.1` 或更高）。遇到兼容性或完整性的提示时，不要用删除同步记录的办法绕过去。

## 接入正式笔记库

1. 先完成上面的测试，并给正式库单独做一份备份。
2. 在 iPhone 上新建一个空白的正式库，关闭 Store in iCloud，按前面的步骤装好固定版本的插件。
3. 填写和 Mac 正式库相同的 WebDAV 地址和用户名，密码在手机上单独输入，点「保存设置」。
4. 「自动同步」先不开，手动运行「立即同步」。同步时让 Obsidian 留在前台，连稳定的 Wi-Fi，接上电源。手机要有足够的空间放下整个库，另外再留一些给临时文件。手机上单个文件最大 128 MiB。
5. 同步完成后，检查笔记、附件和文件数量，再处理弹出的确认窗口。核对数量时以 Mac 上的文件数为准，远端的版本记录数和文件数不是一回事。
6. 确认无误后打开「自动同步」，并点「保存设置」。

不要把 NAS 上的版本目录直接复制到手机当笔记库用，那里面不是按原名存放的笔记。

日常使用时记住两点：同步只在 Obsidian 处于前台时进行；离开应用前，先运行「立即同步」，看到提示「已同步」再离开。

## 更新已安装的插件

不要卸载重装，也不要删除插件文件夹。卸载会连同步记录一起删掉。

1. 备份手机上的本地库。
2. 在 BRAT 的插件列表里编辑 `bitcaoxubo-cyber/obsidian-webdav-versions`，把固定版本改成 `0.4.0`。不需要重新添加仓库。
3. 更新完成后，到插件设置页顶部核对版本号。
4. 所有设备都更新之后，让 Obsidian 留在前台，运行「立即同步」，再处理确认窗口。

固定了版本之后，BRAT 不会自动换到别的版本。下次升级时再改一次固定版本号。

也可以手动更新：关闭 Obsidian，用新版本的 `main.js` 和 `manifest.json` 覆盖 `<手机本地库>/.obsidian/plugins/obsidian-webdav-versions/` 里的同名文件，再打开 Obsidian。改过配置目录名字的，把 `.obsidian` 换成你自己的目录名。同一目录下的 `data.json` 和 `local-state/` 不要动。手机上不方便进这个目录，优先用 BRAT。

已经有笔记的手机，更新插件不需要重建笔记库。电脑端的更新步骤相同，见 [README：更新插件](../README.md#更新插件)。

## 已经卸载重装过怎么办

直接用 `0.4.0` 同步即可。

- 本机文件和这篇笔记的某个历史版本完全相同时，它不会被重新上传。别处已经更新的，本机会更新到最新内容；别处已经删除的，本机文件留着，并出现在确认窗口的「本机的旧副本」里。
- 核对路径后，可以选「删除本机副本」，也可以选「保留并重新同步」。先关掉窗口也没关系，文件会留在本机，不会在下一轮被自动删除。
- 本机文件和所有历史版本都不同时，它会被当成你的修改保留下来，按两台设备同时修改的规则处理。

## 确认窗口

同步结束后，需要你决定的文件会集中列在一个窗口里，主要是「本机的旧副本」「删除冲突」「旧版本冲突」和「空文件夹」四组，普通冲突和还在等待同步的文件也列在里面。各组的含义和操作见 [README：同步后的确认窗口](../README.md#同步后的确认窗口)。

在手机上要留意：

- 删除走 Obsidian 的回收站。如果「设置 → 文件与链接 → 已删除文件」选的是「永久删除」，窗口会拒绝删除。先改成系统回收站或 Obsidian 回收站。
- 普通冲突（两台设备各自改了同一篇）需要你对照两个文件，把内容合并进原文件并保存，然后让原文件保持打开，运行「采用当前文件解决冲突」。

## 手机上的空文件夹

手机不会自动清理空文件夹。文件的删除和移动照常同步，只是可能留下空目录。

做一次完整同步之后，打开「查看同步冲突 → 空文件夹」，核对路径，选「清理」「全部清理」或「保留」。「全部清理」会先让你确认数量。清理是把目录移进回收站；设置成「永久删除」时会拒绝执行。「保留」只对本机有效，可以在设置页重置。

清理时请让 Obsidian 留在前台，不要同时往这些目录里写东西。在插件最后一次检查之后、目录进回收站之前，如果正好有新文件写进去，它会跟着进回收站，可以从回收站恢复。

清理手机上的空文件夹不会影响其他设备。更多细节见 [空文件夹清理](空文件夹清理.md)。

## 出问题时

- 提示同步暂停时，先把提示内容记下来，保留本地库原样。不要删除 `local-state/`，里面可能有还没上传的内容。
- 提示 `HEAD` 不支持或文件超过大小上限时，先解决提示的原因，不要清除同步记录硬试。手机下载附件需要服务器的 `HEAD` 请求返回文件大小。
- 如果再次出现「next 不存在」的错误：保留完整的错误信息和本地库，不要删除恢复目录，也不要手工创建 `next`。插件已有针对它的恢复保护，但这个错误最初的原因还没有查清。
- 这个版本用不了时，先关掉「自动同步」并停用插件，保留本地的全部内容。退回旧版本的步骤见 [README：退回旧版本](../README.md#退回旧版本)。退回也是用覆盖程序文件的方式，不要卸载。
