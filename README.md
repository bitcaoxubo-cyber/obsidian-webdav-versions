# 飞牛 WebDAV 版本同步 · Mac / iPhone

**0.4.0-beta.5：残留空文件夹清理，尚未发布，等待复核。**

本版本为电脑增加同步后的安全空目录清理，并在确认窗口加入「空文件夹」组，处理手机和历史残留目录。沿用 beta.4 的旧副本识别与文件删除确认。详见 [本版说明](docs/RELEASE.md) 和 [空文件夹交付与验收报告](docs/空文件夹清理.md)。

**所有连接同一远端的设备都要升级，才能避免仍在运行旧版的设备把旧文件重新上传。更新请用 BRAT 或覆盖程序文件，不要卸载重装。** 请保留每台设备自己的笔记、设置和 `local-state/`，不要在设备间复制同步记录。

手机空文件夹仍不会自动删除；可以在「查看同步冲突」的第四组中确认清理。仅有空文件夹时不会自动弹窗。

Mac 与 iPhone 各自打开本地 Obsidian 库，通过飞牛现有 HTTPS WebDAV 交换笔记和附件，同时修改会保留双方版本。GitHub 仅分发插件，整个安装及同步流程不依赖 iCloud。需要 Obsidian 1.11.4 或更高版本。

## 目录上限修复

部分 WebDAV 服务在单目录超过 10000 个对象时仍返回看似完整的 XML，但实际漏列对象。旧版会因此暂停。新版保留完整性检查，并支持把对象按哈希首字符分为 16 个目录。**已超过上限的旧库需要显式迁移；只更新插件不会自动移动远端数据。**

- 未迁移的小型旧库继续读写 v1 格式。
- 迁移后使用 v2 布局；记录 ID、父版本关系、正文和附件字节保持不变。
- **所有设备须更新到 0.3.0-beta.1 或更高版本。旧插件不支持新布局，会暂停同步。**
- 迁移先在独立目录验收，保留本地备份与迁移日志。详见 [布局迁移说明](docs/存储布局迁移.md)。

## 更新插件

电脑和手机都可以用 BRAT 更新，步骤相同。当前已发布的固定版本仍是 `0.4.0-beta.4`；`0.4.0-beta.5` 尚未发布，不要在 BRAT 中选择尚不存在的 tag。下面的安装步骤对应已发布版本。

### 用 BRAT 更新（电脑与手机）

1. 先备份各自的本地库，并暂停需要升级的设备上的自动同步。
2. 在电脑或手机的 Obsidian 社区插件中安装并启用 BRAT。已经装好 BRAT 的设备不需要重装它。
3. 在 BRAT 添加 `bitcaoxubo-cyber/obsidian-webdav-versions`；已经添加过的，在 BRAT 插件列表中编辑它，把固定版本改为 `0.4.0-beta.4`。
4. 等待更新完成，检查 WebDAV Versions 设置页显示的版本。固定版本不会随普通自动更新切到其他版本，下次升级时再次编辑固定版本号。
5. 所有设备都升级后，先在各设备保持前台、手动同步并检查确认窗口，再恢复自动同步。

BRAT 的安装与更新只写插件程序文件，保留原有 `data.json` 和 `local-state/`；核实依据见 [BRAT 更新方式](docs/旧副本与删除确认.md#6-brat-的核实结果)。

### 手动更新（电脑与手机）

关闭 Obsidian，用新版本的 `main.js` 与 `manifest.json` 覆盖插件目录中的同名文件，再打开 Obsidian。默认目录是 `<本地库>/.obsidian/plugins/obsidian-webdav-versions/`；如果改过配置目录，请使用对应位置。手机不便访问插件目录时优先使用 BRAT。

只覆盖这两个程序文件，保留 `local-state/`、`data.json` 和笔记。不要先删除整个插件文件夹，也不要用新建空文件夹替换它。

### 不要卸载重装；已经重装时怎么办

卸载会删除整个插件文件夹，包括同步记录。升级时不要卸载，也不要清空 `local-state/`。

如果已经重装，从本版本起，与这篇笔记的历史内容完全相同的旧副本不会再被当成全新内容上传：别处已更新的会更新为最新版本；别处已删除的会原样保留，并出现在确认窗口中。你可以删除本机旧副本，或选择保留并重新同步。与历史内容不同的本地修改仍会保留；不要为了消除冲突而删除同步记录。

## iPhone 安装

1. 在 Obsidian 创建空白库，关闭 Store in iCloud，存放于“我的 iPhone → Obsidian”。
2. 在第三方插件市场安装并启用 BRAT。
3. 在 BRAT 添加 `bitcaoxubo-cyber/obsidian-webdav-versions`，选择固定版本 `0.4.0-beta.4`。先在独立测试库验收，不要自动跟随最新版本。
4. 启用“WebDAV Versions · 飞牛同步”，按 [iPhone 安装与验收](docs/iPhone安装与验收.md) 配置独立的测试 WebDAV 子目录。

首次移动端验收包括 Mac↔iPhone 双向同步、旧副本确认、离线冲突、后台中断恢复和大附件。通过后，再建立手机正式空白本地库接入原有目录。已安装插件的设备按“更新插件”一节保留设置及同步记录，不需要重建笔记库。**本版本尚未完成真实 iPhone 验收。**

## 移动端范围

- 仍可访问未迁移的 v1 旧库；v2 布局需所有客户端升级。修订内容格式与 ID 保持兼容，但旧版不识别新对象路径。
- 本版停止自动清理手机空目录。接收文件删除或移动后，旧空文件夹可能保留；这不代表其中的文件没有同步删除。
- 文件夹本身不单独同步。从未有过同步文件的空目录不会传到其他设备。
- 自动同步只在前台运行。首次加载、回到前台、手动同步、解决冲突、出错后的下一轮和每隔 10 分钟执行全量检查；其他轮次只处理脏路径和远端变化。手机文件变更防抖 15 秒，桌面 5 秒；有传输或本地事件后轮询间隔为 60 秒，连续空闲逐步延长至 120、240、300 秒。
- 有待处理文件时按60→120→240→300秒退避重试；未处于失败重试等待期时，文件有新改动仍按手机15秒、桌面5秒防抖。
- 连续编辑时至少每60秒同步一次，保存事件不会推迟已排轮询。同步失败后等待60秒再试，期间文件事件不会取消等待；网络恢复或回到前台时立即重试。
- 从手机“文件”App 等外部修改而没有 Obsidian 文件事件时，要等下一次全量轮才会发现。可手动“立即同步”提前检查；“深度校验同步”忽略文件哈希缓存，重新读取并校验全部库内文件。修改时间距当前不足 2 秒的文件仍会重读，以防时间戳竞争。
- “查看同步状态”显示本轮耗时、库内文件实际读取次数、内容及状态哈希字节数、实际 HTTP 请求数、全量/增量类型，以及当前轮询间隔。
- 手机单文件上限 **128 MiB**，超限会停止，不会跳过后视作删除；桌面仍为 512 MiB。手机需要足够空间保存当前文件、暂存及待上传内容。
- 手机通过 Obsidian 原生 `requestUrl` 访问 WebDAV，要求 HEAD 返回 Content-Length。超过 4 MiB 的附件优先按 4 MiB 分段下载；服务器忽略 Range 时接收一次受限的完整响应。最终按 SHA-256 校验。中途退出会在下一轮重试该文件，不保证从该文件断点续传。
- 手机仍需要在内存中读写一个完整文件；分段请求不能保证任意 iPhone 都能处理 128 MiB。大附件必须真机测试。
- 配置目录、隐藏文件及设备同步状态不参与笔记同步；手机单独填写密码，使用 Obsidian SecretStorage。
- 请求直接指向可信的 HTTPS WebDAV 地址。原生 requestUrl 没有禁用重定向的公开选项，因此手机应使用不发生跳转的最终地址；桌面仍拒绝重定向。
- 本版没有端到端加密；服务器管理员能读取笔记。

## Mac 安装与首次同步

1. 电脑也可通过 BRAT 安装固定版本，步骤见“更新插件”。手动首次安装时，解压安装包，把整个 `obsidian-webdav-versions` 文件夹放进**测试笔记库**的 `.obsidian/plugins/`。在 Finder 按 `⌘⇧.` 可显示隐藏文件夹。放好后应能找到 `.obsidian/plugins/obsidian-webdav-versions/manifest.json` 和同目录的 `main.js`。在 Obsidian「设置 → 第三方插件」中启用 **WebDAV Versions · 飞牛同步**。同一笔记库只使用一套同步工具。
2. 在飞牛创建一个专属于这份笔记库的文件夹，将它的完整 HTTPS WebDAV 地址填入插件设置。两台 Mac 填相同地址和账号，分别取名如 `MacBook`、`Mac mini`。通过设置里的密钥选择器保存各自的 WebDAV 密码，点「测试连接」，再点「保存设置」。测试连接只验证目录可读，首次同步才验证写入。
3. 在 MacBook 的测试库创建一篇笔记，运行命令「立即同步」。另一台 Mac 用独立的空白测试库连接同一个远端文件夹，运行「立即同步」。看到同样的内容后可打开自动同步。已经有内容的库首次接入时，同一路径存在不同内容会保留两版。远端目录里以前放的普通 Markdown 文件不会自动导入，请从对应的本地库开始。
4. 自动同步需要 Obsidian 打开。桌面编辑停止约 5 秒、手机约 15 秒后进行增量同步；连续编辑时至少每 60 秒同步一次。空闲轮询从 60 秒逐步延长至 300 秒，每 10 分钟全量检查。失败后等待 60 秒再试，网络恢复或回到前台时立即重试。手动同步总是全量扫描，可从左侧刷新按钮、状态栏或命令面板发起。

## 两台 Mac 同时修改

从同一版本出发，暂时断开网络或关闭自动同步。分别修改同一篇笔记，写入不同的一句话。恢复连接，先在两端各同步一次，再让先上传的设备同步一次。两台 Mac 会显示相同的一篇正文和一份同目录的 `笔记名 (sync-conflict 设备名 版本号).md`。普通接续编辑只更新原文件。PDF 和图片的冲突也保留独立文件，扩展名保持原样。

用命令「查看同步冲突」打开统一确认窗口。普通的双方独立修改仍需先比较，必要时手工合并并保存，再用「采用当前文件解决冲突」。若另一端又有新修改，插件会要求重新同步和比较。

## 同步后的确认窗口

一轮同步结束后，窗口集中列出三类需要决定的文件：

- **本机的旧副本**：别处已经删除，本机留着未改变的旧内容。可以删除本机副本，或保留并重新同步；也可以暂时关闭窗口，文件会留在本机。
- **删除冲突**：一边删除，另一边保留了文件。标为「内容与删除前相同」的可以批量删除；「删除后有改动」的只能逐个决定。
- **旧版本冲突**：一边仍是旧内容，另一边已有较新内容。可以逐个或批量采用较新版本。

批量操作会先确认数量。文件在窗口打开后被修改、仍有未保存输入，或冲突已经变化时，会跳过该文件并提示跳过数量。一次确认只进行一轮同步。

确认删除使用 Obsidian 的回收站接口。**如果“设置 → 文件与链接 → 已删除文件”选择了“永久删除”，此窗口会阻止删除；先选择系统回收站或 Obsidian 回收站，再继续。** 窗口不会因你关闭它而删除文件，也不会在条目不变时每轮重新弹出；可以随时用「查看同步冲突」打开。


## 空文件夹

电脑接收其他设备的删除或移动并在本机实际移除文件后，会用系统的非递归删除清理空父目录，逐层向上，遇到任何内容就停。即使只是 `.DS_Store` 或一个无关空子目录，也会保留。你在另一设备上清空但故意留着的文件夹，可能因此在电脑上消失；以后放入文件时会重新创建。

本机用户自己删除文件留下的目录、历史残留目录和手机上的空目录，都在全量同步后进入「查看同步冲突 → 空文件夹」。只列有同步历史且没有有效内容的最上层目录；从未放过同步文件的空目录、隐藏目录、配置目录不列出。仅有这一组不会自动弹窗，状态详情显示可清理的数量。每行可「清理」「保留」，也可批量操作；「全部清理」先确认数量。

「保留」仅作用于本机，把这个目录及子树排除出清理；包含保留目录的上层目录也会保留。名单写在本机插件设置中，重启仍有效。设置页显示「已保留 N 个空文件夹」，按「重置」清空名单，下次全量同步重新识别。

电脑上完全不含文件的目录用系统非递归删除，永久删除设置不影响这条安全路径。手机目录，以及电脑上只含 `.DS_Store` 的目录，必须经 Obsidian 回收站；设置为永久删除、设置不可读或接口缺失时拒绝。清理前会重新检查内容、同步状态和前台状态；打开的笔记编辑器、目录下新事件都会使回收站清理跳过。系统回收站明确拒绝时也会报告跳过。

**回收站路径仍有一个已知空档：最后检查之后、原生移入回收站之前写入的新文件可能随目录进入回收站，可以恢复。** 因此清理时保持 Obsidian 在前台，避免同时编辑或让其他程序往这些目录写入。电脑的非递归删除不会删除任何文件。

空文件夹没有远端记录。清理本身不读写远端，不改变同步协议或 `local-state/` 格式；目录事件随后可能触发一次全量同步。手动清理一台设备的空目录不会传到其他设备，其他设备各自在窗口里清理；旧版设备不会获得本版清理功能。**电脑和 iPhone 真机清理尚未验收**，步骤与填写栏见交付报告。

## 存储和范围

- 本地笔记及附件保持原来的目录结构。同步范围是库内所有普通可见文件，支持论文标题中的英文冒号。扫描时跳过隐藏项目、Obsidian 配置目录和符号链接，不会读取链接指向的文件。如果已同步的笔记或远端需要写入的路径被符号链接占用，插件会暂停同步并保留远端版本。特殊文件、保留名称以及无法安全区分的文件名也会暂停同步。文件名中请勿使用 ` (sync-conflict `，这是插件生成副本专用的标记。
- 日常同步需要 HTTPS Basic 认证、`PROPFIND`、`MKCOL`、`GET` 和 `PUT`；布局迁移另需 `MOVE`。使用受信任的 TLS 证书。NAS 里的 `obsidian-webdav-versions-v1/` 或迁移后的 `obsidian-webdav-versions-v2/` 是插件管理的版本目录，内容是按校验值命名的原始文件和版本记录。记录保留原路径、父版本和设备名称。远端管理员可以读取这些数据，本版没有端到端加密。
- 插件先校验文件内容，再发布引用它的新版本。同一内容可共用存储；不同版本拥有不同地址。重新连接时使用本机上次实际拿到的版本来判断冲突。缺失的已知版本、不完整的远端目录或校验错误都会暂停同步。若插件提示本地恢复文件，请保留提示的文件并检查原因。
- 版本采用追加存储，删除与合并只追加记录。空间随历史增长，本版不提供历史清理，也不提供任意版本的可视化浏览。桌面单个文件上限 512 MiB，手机为 128 MiB。重命名按旧路径删除、新路径新增记录。NAS 上看不到按原名排列的 Markdown 镜像；在一份新的空白 Obsidian 库中同步，可以重建当前正文和冲突副本。
- 命令「测试连接」和离线单元测试都不能替代真实飞牛验收。源项目内的 `scripts/verify-webdav.js` 可用两份临时本地笔记库在飞牛上实际检查并发写入。它会在所选 WebDAV 文件夹下新建独立的测试子目录，运行结束后可自行删除该测试子目录。

## 开发

基于 leopard530/obsidian-sync-webdav 的提交 `1ed8b7876e206b3efc0e54537b30b53f0ad92c7c`。沿用插件入口、文件变更触发与 WebDAV 请求方式，替换了会覆盖同名文件的同步实现。来源与许可证见 `NOTICE` 和 `LICENSE`。采用单独的插件 ID，可与上游安装目录区分。

在有 Node.js 22 或更高版本的环境中，运行 `node --test test/*.test.js`，再运行 `node scripts/build.js` 生成可安装的 `main.js`。运行不需要 npm 安装、数据库或另外部署服务。

## 本地状态与回退

新版本直接读取 0.3.0-beta.1 的状态与未完成日志，不需要清空 `local-state/`。新增独立待处理日志和可重建的移动端哈希缓存；修订 JSON、ID、blob 和 v1/v2 远端布局不变。同布局下可与旧版本交换数据，但旧版没有本次旧副本识别与确认保护。要避免旧设备重新上传已删除内容，请更新所有连接该远端的设备。

直接在一次中断后换回 0.3.0-beta.1 不安全：旧版本不会读取新独立待处理日志。先备份整个库（含 `local-state/`），用新版本在前台成功完成手动全量同步，确认无错误、待处理项为 0、无独立 pending，停用插件后再降级。若新版本不能恢复，保留全部现场和未同步内容，使用新的空白测试库核对恢复，勿删状态强行重试。详见性能报告。
