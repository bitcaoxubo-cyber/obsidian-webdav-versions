# 飞牛 WebDAV 版本同步 · Mac / iPhone

Mac 与 iPhone 各自打开本地 Obsidian 库，通过飞牛现有 HTTPS WebDAV 交换笔记和附件，同时修改会保留双方版本。GitHub 仅分发插件，整个安装及同步流程不依赖 iCloud。需要 Obsidian 1.11.4 或更高版本。

**0.4.0-beta.1 优化空闲同步、状态保存及批量传输；移动端仍为测试版，尚未完成 iPhone 真机验收。此评审分支未发布 Release。**

## 目录上限修复

部分 WebDAV 服务在单目录超过 10000 个对象时仍返回看似完整的 XML，但实际漏列对象。旧版会因此暂停。新版保留完整性检查，并支持把对象按哈希首字符分为 16 个目录。**已超过上限的旧库需要显式迁移；只更新插件不会自动移动远端数据。**

- 未迁移的小型旧库继续读写 v1 格式。
- 迁移后使用 v2 布局；记录 ID、父版本关系、正文和附件字节保持不变。
- **所有设备须更新到 0.3.0-beta.1 或更高版本。旧插件不支持新布局，会暂停同步。**
- 迁移先在独立目录验收，保留本地备份与迁移日志。详见 [布局迁移说明](docs/存储布局迁移.md)。

## iPhone 安装

1. 在 Obsidian 创建空白库，关闭 Store in iCloud，存放于“我的 iPhone → Obsidian”。
2. 在第三方插件市场安装并启用 BRAT。
3. 本分支的 `0.4.0-beta.1` 尚未发布到 BRAT。评审用安装文件由 `node scripts/build.js && node scripts/package.js` 生成到 `dist/`；在独立测试库手动安装。待维护者另行发布测试版后，BRAT 添加 `bitcaoxubo-cyber/obsidian-webdav-versions` 并固定该版本。
4. 启用“WebDAV Versions · 飞牛同步”，按 [iPhone 安装与验收](docs/iPhone安装与验收.md) 配置独立的测试 WebDAV 子目录。

首次移动端验收包括 Mac↔iPhone 双向同步、离线冲突、后台中断恢复和大附件。通过后，再建立手机正式空白本地库接入原有目录。

## 移动端范围

- 仍可访问未迁移的 v1 旧库；v2 布局需所有客户端升级。修订内容格式与 ID 保持兼容，但旧版不识别新对象路径。
- 自动同步只在前台运行。首次加载、回到前台、手动同步、解决冲突、出错后的下一轮和每隔 10 分钟执行全量检查；其他轮次只处理脏路径和远端变化。手机文件变更防抖 15 秒，桌面 5 秒；有传输或本地事件后轮询间隔为 60 秒，连续空闲逐步延长至 120、240、300 秒。
- 从手机“文件”App 等外部修改而没有 Obsidian 文件事件时，要等下一次全量轮才会发现。可手动“立即同步”提前检查；“深度校验同步”忽略文件哈希缓存，重新读取并校验全部库内文件。修改时间距当前不足 2 秒的文件仍会重读，以防时间戳竞争。
- “查看同步状态”显示本轮耗时、库内文件实际读取次数、内容及状态哈希字节数、实际 HTTP 请求数、全量/增量类型，以及当前轮询间隔。
- 手机单文件上限 **128 MiB**，超限会停止，不会跳过后视作删除；桌面仍为 512 MiB。手机需要足够空间保存当前文件、暂存及待上传内容。
- 手机通过 Obsidian 原生 `requestUrl` 访问 WebDAV，要求 HEAD 返回 Content-Length。超过 4 MiB 的附件优先按 4 MiB 分段下载；服务器忽略 Range 时接收一次受限的完整响应。最终按 SHA-256 校验。中途退出会在下一轮重试该文件，不保证从该文件断点续传。
- 手机仍需要在内存中读写一个完整文件；分段请求不能保证任意 iPhone 都能处理 128 MiB。大附件必须真机测试。
- 配置目录、隐藏文件及设备同步状态不参与笔记同步；手机单独填写密码，使用 Obsidian SecretStorage。
- 请求直接指向可信的 HTTPS WebDAV 地址。原生 requestUrl 没有禁用重定向的公开选项，因此手机应使用不发生跳转的最终地址；桌面仍拒绝重定向。
- 本版没有端到端加密；服务器管理员能读取笔记。

## Mac 安装与首次同步

1. 解压安装包，把整个 `obsidian-webdav-versions` 文件夹放进**测试笔记库**的 `.obsidian/plugins/`。在 Finder 按 `⌘⇧.` 可显示隐藏文件夹。放好后应能找到 `.obsidian/plugins/obsidian-webdav-versions/manifest.json` 和同目录的 `main.js`。在 Obsidian「设置 → 第三方插件」中启用 **WebDAV Versions · 飞牛同步**。同一笔记库只使用一套同步工具。
2. 在飞牛创建一个专属于这份笔记库的文件夹，将它的完整 HTTPS WebDAV 地址填入插件设置。两台 Mac 填相同地址和账号，分别取名如 `MacBook`、`Mac mini`。通过设置里的密钥选择器保存各自的 WebDAV 密码，点「测试连接」，再点「保存设置」。测试连接只验证目录可读，首次同步才验证写入。
3. 在 MacBook 的测试库创建一篇笔记，运行命令「立即同步」。另一台 Mac 用独立的空白测试库连接同一个远端文件夹，运行「立即同步」。看到同样的内容后可打开自动同步。已经有内容的库首次接入时，同一路径存在不同内容会保留两版。远端目录里以前放的普通 Markdown 文件不会自动导入，请从对应的本地库开始。
4. 自动同步需要 Obsidian 打开。桌面编辑停止约 5 秒、手机约 15 秒后进行增量同步；远端轮询从 60 秒逐步延长至 300 秒，每 10 分钟全量检查。手动同步总是全量扫描，可从左侧刷新按钮、状态栏或命令面板发起。网络恢复后插件会再次尝试同步。

## 两台 Mac 同时修改

从同一版本出发，暂时断开网络或关闭自动同步。分别修改同一篇笔记，写入不同的一句话。恢复连接，先在两端各同步一次，再让先上传的设备同步一次。两台 Mac 会显示相同的一篇正文和一份同目录的 `笔记名 (sync-conflict 设备名 版本号).md`。普通接续编辑只更新原文件。PDF 和图片的冲突也保留独立文件，扩展名保持原样。

用命令「查看同步冲突」定位笔记。比较后可以打开想保留的副本，或先在正文里手工合并并保存。对要作为最终内容的文件运行「采用当前文件解决冲突」并确认，随后在另一台同步。若另一端又有新修改，插件会要求重新同步和比较。删除与修改同时发生时，先保留修改过的正文并显示冲突；若决定删除，先解决冲突，再删除已确认的正文并同步。

## 存储和范围

- 本地笔记及附件保持原来的目录结构。同步范围是库内所有普通可见文件，支持论文标题中的英文冒号。扫描时跳过隐藏项目、Obsidian 配置目录和符号链接，不会读取链接指向的文件。如果已同步的笔记或远端需要写入的路径被符号链接占用，插件会暂停同步并保留远端版本。特殊文件、保留名称以及无法安全区分的文件名也会暂停同步。文件名中请勿使用 ` (sync-conflict `，这是插件生成副本专用的标记。
- 日常同步需要 HTTPS Basic 认证、`PROPFIND`、`MKCOL`、`GET` 和 `PUT`；布局迁移另需 `MOVE`。使用受信任的 TLS 证书。NAS 里的 `obsidian-webdav-versions-v1/` 或迁移后的 `obsidian-webdav-versions-v2/` 是插件管理的版本目录，内容是按校验值命名的原始文件和版本记录。记录保留原路径、父版本和设备名称。远端管理员可以读取这些数据，本版没有端到端加密。
- 插件先校验文件内容，再发布引用它的新版本。同一内容可共用存储；不同版本拥有不同地址。重新连接时使用本机上次实际拿到的版本来判断冲突。缺失的已知版本、不完整的远端目录或校验错误都会暂停同步。若插件提示本地恢复文件，请保留提示的文件并检查原因。
- 版本采用追加存储，删除与合并只追加记录。空间随历史增长，本版不提供历史清理，也不提供任意版本的可视化浏览。桌面单个文件上限 512 MiB，手机为 128 MiB。重命名按旧路径删除、新路径新增记录。NAS 上看不到按原名排列的 Markdown 镜像；在一份新的空白 Obsidian 库中同步，可以重建当前正文和冲突副本。
- 命令「测试连接」和离线单元测试都不能替代真实飞牛验收。源项目内的 `scripts/verify-webdav.js` 可用两份临时本地笔记库在飞牛上实际检查并发写入。它会在所选 WebDAV 文件夹下新建独立的测试子目录，运行结束后可自行删除该测试子目录。

## 开发

基于 leopard530/obsidian-sync-webdav 的提交 `1ed8b7876e206b3efc0e54537b30b53f0ad92c7c`。沿用插件入口、文件变更触发与 WebDAV 请求方式，替换了会覆盖同名文件的同步实现。来源与许可证见 `NOTICE` 和 `LICENSE`。采用单独的插件 ID，可与上游安装目录区分。

在有 Node.js 22 或更高版本的环境中，运行 `node --test test/*.test.js`，再运行 `node scripts/build.js` 生成可安装的 `main.js`。运行不需要 npm 安装、数据库或另外部署服务。

## 本地状态与回退

新版本直接读取 0.3.0-beta.1 的状态与未完成日志，不需要清空 `local-state/`。新增独立待处理日志和可重建的移动端哈希缓存；修订 JSON、ID、blob 和 v1/v2 远端布局不变。同布局下可与旧版本混用。

直接在一次中断后换回 0.3.0-beta.1 不安全：旧版本不会读取新独立待处理日志。先备份整个库（含 `local-state/`），用新版本在前台成功完成手动全量同步，确认无错误、待处理项为 0、无独立 pending，停用插件后再降级。若新版本不能恢复，保留全部现场和未同步内容，使用新的空白测试库核对恢复，勿删状态强行重试。详见性能报告。
